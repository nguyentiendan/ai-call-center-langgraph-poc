# Example conversations (actual runs, sanitized)

Generated by `uv run python scripts/run_demo.py`. PIN values are never shown.

## Happy path (billing)
- User: `今月の携帯料金が先月より高いのですが。` → `AWAITING_INPUT / collect_customer_id`「デモ用のお客様IDを入力してください。」
- User: `CUST-1001` → `AWAITING_INPUT / collect_pin`「デモ用PINを専用入力欄から入力してください。」
- Verify (専用欄): → `CLOSED / close`「2026-10のご請求は8,800円、2026-09は6,600円です。差額は2,200円です。内訳は基本料金5,500円、データ超過2,200円、オプション1,100円です。」
- Trace: classify_intent→billing_inquiry, collect_customer_id→awaiting_input, collect_customer_id→supplied, collect_pin→awaiting_input, verify_identity→verified, get_billing→found, explain_bill→completed, close→closed

## FAQ
- User: `営業時間は何時ですか？` → approved FAQ (平日9時から18時, fictional), `CLOSED`. No verification, no billing call.

## Handoff
- User: `オペレーターに代わってください` → `HANDOFF`, ticket `DEMO-********`, explicitly `queued_demo` (no live operator).

## Verification lockout (failure case)
- 3 wrong PIN submissions (`verify_identity→retry` twice, then `→locked`) → one `HANDOFF` ticket, billing never called. Further `/verify` returns 409.

## Billing timeout (failure case)
- Verified, then simulated timeout: exactly 2 billing attempts (initial + 1 retry) → `get_billing→error` → `HANDOFF`.
